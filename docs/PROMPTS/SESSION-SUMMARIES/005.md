# Session 005

**Date:** 2026-07-09
**Working with:** builder (Blaine)
**Phase:** Playtest & iterate → **Design** (pivoted to designing the process, not the game)

## Summary

A process-design session. Blaine asked for "a good process for getting the ground framework
solid" — base rules, the modified rules each deck introduces, and a smart way to lock in what
every card does — kept consistent, editable, and saved as a canonical baseline the rest of the
project builds on. Rush was the cautionary tale: cards were LLM-generated from assumptions that
no longer hold, so even the cards need reworking to match the current rules.

The read that anchored the session: the rules layer is solid, but the card layer is drifted —
the CSV openly self-flags it (Overextend inert on ~15 red actions, "this turn" everywhere,
a dozen ⚑ "needs design" notes). The structural cause is that there are **three** layers of
truth — base rules, per-deck rules, cards — and only base rules and cards were ever written
down. The **missing middle** (what a deck's mechanics mean + the invariants its cards must obey)
is why Rush drifted: cards had nothing to be consistent *against*. The cure is canonical-first.

Designed the system across a few decisions, each confirmed by Blaine: (1) the cards need **both**
mechanical normalization *and* genuine redesign, tracked separately, with a hard sequence — lock
the rules canon first, then churn cards until two clean decks sit on top; (2) "finalize the
rules" is really two artifacts — a base-rules canon (≈90% done; a decision sprint over the open
⚑ questions, not a rewrite) plus a **charter per deck**, the first-class version of the middle
layer; (3) card truth flips to the CSV as the single source of truth (verified this session that
the CSV round-trips a full card losslessly), retiring the dormant TS/overrides split-brain and
deliberately overturning decision 45's "TS authoritative until admin UI" holding pattern; (4) a
branch → PR → agent-review loop where the agent answers three questions per card PR (valid?
consistent text↔effects? in-charter?), with a `status` column (`canon`/`draft`/`redesign`)
that makes "locked in" concrete and feel/balance left to humans.

The full design is captured in `docs/superpowers/specs/2026-07-09-canon-and-card-authoring-design.md`.
No code or rules changed this session — it was design only. Blaine wrapped to switch to Fable
in a fresh session (remote terminal couldn't switch models mid-session) and asked for a clean
push with everything up to date.

## Decisions

- Card rework is job (c): **normalize and redesign, tracked separately**; rules canon is locked *before* card churn begins.
- "Finalize the rules" = two artifacts: **base-rules canon** (stamp `game-rules.md` proto → v1.0 over the open ⚑ questions) + **a charter per deck** (identity · allowed keywords · invariants · curve · influence posture) — the formalized middle layer.
- **Decision 1 = A:** `data/cards.csv` becomes the single source of truth; engine generates from it; `red.ts`/`yellow.ts` retire; types + `validateCardSet` stay. Overturns decision 45's TS-authoritative holding pattern, on purpose.
- Anti-drift rule: every card must satisfy **two parents** — base rules + its deck charter.
- Authoring loop: `status` column (`canon`/`draft`/`redesign`); normalize lane (agent proposes, humans ratify) vs redesign lane (Griff's prose intent → agent structures → why to DECISIONS.md); agent is the PR gate (no CI, per decision 45) answering valid / consistent / in-charter; feel + balance stay human.
- Division of labor: Griff owns feel + tunable columns + redesign intent; agent owns structure + normalization + review; both ratify.
- Canon is versioned via git tag (`canon-vN.M`) + a thin `docs/canon/CANON.md` index — locked baseline, not frozen; new rules cut a new version.
