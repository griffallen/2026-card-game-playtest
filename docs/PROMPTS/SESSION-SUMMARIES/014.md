# Session 014

## Summary

Blaine opened with a maintenance complaint: nobody could tell which documents were canon, and
lots of it was out of date. He wanted a plan he and Griff could work through together. The
documents turned out to be the symptom.

Three parallel audits found the shape of it. Four documents each claimed authority over the
rules and had drifted apart — `CLAUDE.md` named `rules-v1.3.md` authoritative while the engine
built against `SPECS/game-rules.md`, which was itself written as *deltas from v2.3*, so no single
document stated the current rules at all. Reconstructing them meant three files and two diffs.
The "authoritative" one taught a turn structure the engine never had, a face-down resource
mechanic that was never built, Prison as a live keyword after it was cut, and a `-15` influence
threshold left behind by a half-finished edit at decision 106.

The fix came from a question Blaine asked rather than anything the audits proposed: could the
rulebook be maintained in the `.tsx` and the doc generated from it? The demo's rules page was
already correct on every single value — it is what players read on the only surface anyone
plays, so it was the copy that had stayed honest. It became the source. `docs/rules.md` is now
generated from it and gated, with an engine-parameter table read straight from `V3_RULES` and a
stated tiebreak: if the prose disagrees with the table, the table is right and the prose is a bug.

Then Blaine reframed the process problem in a way that fixed two things at once. `major` had
always been meant to measure *impact*, but the written rule had quietly substituted *which files
you touched* — two of its three clauses named files. That substitution had over-priced doc upkeep
into rot (`DECISIONS.md` stalled at 106 while 33 commits landed) and, worse, had blocked Griff
from making cards: "changes what a card does" made any new card a `major` requiring Blaine to fire
a build. Scope now means blast radius, card work is never `major`, and the line between a card and
a mechanic is drawn by `cards:check` rejecting unknown ops rather than by an agent's judgement.

The engine audit was the surprise. The balance harness had been passing no rules argument and
silently running legacy v2.3 combat for nine days — every quoted matchup measured a game nobody
plays. Yellow-vs-purple read 65/35 under intercept and 43/57 under real v3, a complete reversal
that voided the sim evidence under decisions 99–106 and the whole "yellow is overpowered" read.
Auditing every caller found it in four places, including the demo's own Simulate tab, so it was
never one careless line but an unsafe default everything inherited. Making `rules` required found
the last two. Griff had been saying for days the numbers felt wrong; he was right.

Three more of the same shape followed: the corpus fingerprinted every game by an engine version
that had never moved off `0.1.0` while combat changed twice; the multiplayer lobby seeded v2.3 and
would have dealt pre-v3 rules to whoever opened it first; and four keywords cut by ruling were
still *implemented* — `flying` would still have let a unit move to any zone. Each was a system
confidently asserting something untrue with nothing checking it against the engine. That is the
through-line, and it is also the answer to why the Chronicler kept getting confused: not the
model, the inputs.

Two process artefacts came out of Blaine noticing he could not tell what he was being asked.
Every Chronicler comment now opens with an action header — who decides, the one ask, what happens
if they say nothing, what is blocked — and #129 "The Board" is a pinned index of open decisions by
owner that the tick rebuilds. The `IF YOU SAY NOTHING` line is the load-bearing one: it makes
silence a choice with a known outcome instead of an open loop a human has to carry.

Finally #114 — Griff's four UI asks, approved on 7/16, never built, his "what's the status of
this?" unanswered for days — was built and shipped, and the closing comment led with the apology
and a correction he was owed: he had been told Reach and Flying were still live keywords, and his
instinct that they were gone was right twice over.

Released as v0.7.0, deployed, 581 tests green.

## Decisions

- The rulebook is authored in `apps/demo/src/pages/Rules.tsx`; `docs/rules.md` is generated from it and gated by `rules:doc:check` — one source, so the demo and the docs cannot disagree.
- Two-authority model ratified (#119): engine + `data/cards` = what the game does; `DECISIONS.md` = why; every prose surface derived and checked, never a rival authority.
- Scope means blast radius, not files touched. Card work is never `major` — the designer must never be blocked from designing.
- The card/mechanic boundary is decided by `cards:check` rejecting unknown ops, not by agent judgement.
- A `docs` lane exists for zero-impact work, agent-committed under a machine-checkable guard — with rulebook prose excluded, because nothing checks prose against the engine.
- `simulateGame`'s `rules` is required; forgetting it must be a compile error, not a wrong answer.
- Rules version = engine package version = `3.2.0`, pinned by a test; MINOR bumps on combat-behaviour change.
- Cut keywords are deleted from the engine; the `overextend` wire field is retained (always rejected) for corpus replay. Prison is blocked at the validator but not yet removed.
- Delete superseded docs rather than archiving them — git holds history, and an archive tree is a second place to find the wrong answer.
- The Chronicle journal is retired: it narrated the build instead of teaching the game.
- Every GitHub comment opens with an action header; one ask per comment; `IF YOU SAY NOTHING` is mandatory.
- **Heuristic sims bound the truth, they don't tell it** (Blaine): fixing #98 made the numbers honest about which *game* they played, not about who played it. Red is fine for now; a balance pass with trustworthy numbers waits on a better bot (#97/#98).
