## Summary

Blaine asked for the whole first loop in one night: reconcile the design, stand up a deployable two-player prototype, and document how the game actually plays — with the explicit understanding that every design call made along the way is provisional and flagged for the designer.

The design pass found that rules v1.2 and the July 5 card sheets disagree in load-bearing places. The two biggest: **the rules define zones but no movement** (armies could never meet), and **the Main Phase text ("an attack is one action") contradicts a separate sequential Combat Phase**. The prototype resolves these — movement as an exhausting action, combat merged into the alternating main phase — plus 28 more recorded calls: "base" = the player, Overextend-on-actions = ceding Influence, "Influence: +N" = on-entry gain, prison release below 0 influence, one-attacker-one-target combat, and per-card rulings for everything undefined (Flying, Radiant Citadel's "maximum Influence," auto-picked imprison targets…). All 30 live in `DECISIONS.md`; every affected card carries a ⚑ note visible in the card browser.

Then the whole stack got built: a pure deterministic engine (all 84 sheet cards as structured, validated effect data — never free text, so admin edits can't silently break games), an event-sourced Fastify server (games replay from their action logs; undo is deleting an event), and a fantasy-clean React table (click-to-act driven entirely by the engine's legal-action list, influence tug-track, chronicle log, spectators, presence). Card art was sliced out of the two deck-sheet PNGs (84 crops); admin-created cards get deterministic procedural SVG art. Admin hall: users, games, engine-validated card editor + forge, deck forge with legality meter, versioned rules parameters.

Two discoveries worth the designer's attention: (1) **prison decay had to resolve before start-of-turn triggers** — otherwise a turn-start imprison at 0 influence breaks its own prison instantly (now a documented ruling); (2) the simulation harness (150 random-policy games per test run, all finishing clean) shows **influence wins dominating 87/13 and the red deck winning 1%** under random play — random ≠ human, but the direction says the influence economy needs eyes. Candidate knobs are listed in GAME-FLOW.md.

Verified end-to-end: 65 tests green (engine 57, server 8), plus real-browser verification — two Chrome sessions registered, created/joined a table, and played 26 actions through the actual UI (banking, deploys, targeted plays, mass imprisonment rendering with chain overlays). Docker image + fly.io/Neon deploy path written and rehearsed against local Postgres.

## Decisions

All 30 in `docs/DESIGN/DECISIONS.md` (each with its reason, all ⚑ pending designer review). Headlines:

1. Movement exists: adjacent-zone move, exhausts the unit (D5) — the game is unplayable without it.
2. Main/Combat merged: alternating actions, attack = one action, one attacker → one target (D8, D10).
3. Off-turn card plays allowed — the per-round interaction the GENESYS asks for (D9).
4. "Base" = the player; attackable only from inside their Home zone (D6).
5. Overextend on actions = shift Influence toward the opponent (D14) — Red pays in the shared argument.
6. "Influence: +N" lines = one-time on-entry gain (D15).
7. Prison: decay before triggers; release when jailer's influence < 0; unit-sourced prisons die with their source (D16 + session ruling).
8. Cards are structured data validated by the engine; games snapshot cards+rules at creation (D26-27).
9. Tech per the seeded stack doc; scrypt auth, no auth dependency; tsx runtime in prod (D3).
10. First player draws 1 on turn one (D19, parameterized like everything else).
