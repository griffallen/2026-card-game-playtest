# Genesys Doc

This project is a card game that is currently in development. It will serve several primary purposes:
    - cleaning up documentation (currently in docx/xlsx format) into a spec format that we can iterate on
    - creating a prototype so that we can play online and rapidly iterate on rules and mechanics
    - allowing for an admin system so that we can make decks for rapid play and iteration

The game itself is a card game but the rules are expected to change over time as we learn how to balance it. The current set of rules are in docs/references/New Game Rules 1.2 July 3, 2026 - earlier rules should be considered superceded. The spreadsheet (New Game June 2026.xlsx) also has some tabs that rough out potential decks, and the Red/Yellow Deck documents show example cards that were generated by an LLM (but we'll want to re-generate our own, leaving graphics for later I think).

At a minimum, we want to do this in a few phases:
    - Clarify the core mechanics and create a series of rules that are somehow easily editable (text files at first but it would be rad if we had a clean admin way of doing this... maybe not possible). At a minimum, being able to balance numeric params, bonuses, win conditions etc. would be awesome so we can create versions of the rules for easy testing - and any core mechanics (actions, flow, etc) can be versioned and tucked into code.
    - Be able to build a deck, select from the library of cards, and save to a user's account for play
    - Be able to manage the library of cards from an admin perspective: names, bonuses, mechanics, new cards, etc. Once the rules are stable, the cards should be able to be tweaked by the game designer through the web UI
    - Play mode: Play a game with two local players (or one game designer acting as both) to test mechanics and gameplay
    - Play mode: Play a game with two network players to explore the game and see how it ends up
    - Play mode: Play a game with a local AI player (simple at first) to ensure mechanics are working and test out game play

What would be amazing as well would be to have a full test suite that runs through the agreed upon rules, simulates a variety of games, and ensures that gameplay can be completed (no runtime bugs), win conditions are possible, and as an extention we could test overall balance and monte-carlo style simulation on a given deck and/or rule version to ensure that things are fair and interesting.

Eventually this will be an online system for community gaming but phase 1 is clear: solidifying the rules, allowing for my friend to quickly iterate (they're the game designer but not a software engineer - I'm the builder but not the game designer). I want to get this deployed up so we can play together and have fun.

Additionally - let's figure out if we want to have a master spec doc that is the living guidelines for the project, or if we can stand this up with all configurable rules. I imagine that the engine itself will manage the game state (card locations, health/status, table zone status, turn flow, etc) - and we can parameterize various conditions (bonuses, win conditions, etc) as well as customize how cards behave in the various turns.

Would prefer this to be a clean project using stable and maintainable tech. Will deploy up to a cheap cloud vps or app service to start. Likely postgres + nodejs stack unless there is a compelling engine or reason to pick something else (dotnet, rails, python etc).
